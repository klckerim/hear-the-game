## 2. Latency on the deployed URL: `eval/latency.py`
`python -m eval.latency --url wss://<app>/ws --sessions 1 --minutes 3`, then `--sessions 10`. Run from the owner's machine.
p50/p95 of: connect -> `hello`; `state` inter-arrival vs nominal 200 ms; wall-clock delay from `insight` to its `speech`; share of `speech`
by `source` (cache / llm / template). Use the default casual mode (demo path, mostly cache hits) and one run in `analyst` mode (more
cache misses, so live Foundry calls are measured from outside too).
Write `eval/results/latency.md` with date, client location (Istanbul -> Sweden Central), sessions, mode. State plainly: client audio latency is not
measured; the client adds a fixed 300 ms jitter buffer; dropped stale speech is only visible in the App Insights metric `htg.speech.dropped_stale`
(owner reads it from the portal and adds the number if available).

- Input: `eval/results/narration_samples.jsonl` from step 1.

- Look up the current Foundry cloud-evaluation SDK with the `microsoft-learn` MCP first (`cloud-evaluation-datasets`, sample

  Note that an LLM judge on Turkish is weaker evidence than on English.
