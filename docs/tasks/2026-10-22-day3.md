# Day 3 (2026-10-22): verified narration and real voices

Goal: every spoken Insight becomes a short EN + TR sentence written by a Foundry model, checked by a deterministic
Verifier (template fallback on failure), voiced by Azure AI Speech, cached, and played in `web/live.html` with ducking.
The demo match is pre-generated, so the demo never waits for a model. Keep it simple; see "Scope and token budget" in CLAUDE.md.

Done when:
- `HTG_ENV=azure python -m htg.narration.pregen --seed <demo seed>` fills `data/cache/` with verified text and MP3 clips.
- `python -m services.engine.run_local --seed <demo seed> --start-minute 10` plays Azure voice clips from cache
  (no model call during the demo); with `HTG_ENV=local` it still runs with template text + browser `speechSynthesis`.
- `python -m eval.narration --seeds 11-30 --limit 100` writes `eval/results/narration.md` (first-pass rate, fallback rate,
  latency p50/p95, Verifier catch rate on mutated sentences).
- `ruff check . && pytest` pass without Azure credentials; CI is green on `main`.

Not building today: Agent Framework workflow, a separate Localizer agent, Blob storage, Recap, SSML styles, MAI-Voice.
One model call writes both EN and TR. The Verifier is plain Python. These are deliberate cuts; README may describe them
as the production path, labeled "not built".

## PR 0: warm-up fix (small, first)
`--start-minute` currently starts the replay at that minute, so detector windows (5-8 min) and baselines start empty.
Fix in `run_local`: feed items from minute 0 at `speed=inf` through `LivePipeline` without publishing, then switch to
paced replay from `start_minute`. Test: Insights emitted after minute 10 are identical with and without `--start-minute 10`.
Merge `day2/state-engine` into `main` first if it is not merged yet.

## PR 1: Narrator + Verifier (no Azure needed to test)
1. `htg/adapters/base.py`: add `Narrator` (`write(insight, feedback=None) -> dict` with `en`, `tr`, `used_facts`) and
   `Speech` (`synthesize(text, lang) -> bytes | None`). Local implementations: template narrator, `Speech` returning `None`.
   `HTG_ENV` picks local or azure. Azure SDKs go in an optional extra `.[azure]`, imported lazily, so CI never needs them.
2. `htg/narration/verifier.py`, pure, one function `verify(text, lang, insight, known_names) -> list[str]` (empty = pass):
   - Numbers: every number in the text (regex, TR comma decimals normalized) must equal a numeric `claim_facts` value
     or its rounding to 0 or 1 decimals. Score "2-1" is two numbers.
   - Names: `known_names` = all players and team names (EN, TR) from `meta.json`. Any known name in the text that is not
     a string in `claim_facts` fails (substring match, so Turkish suffixes like "Aksoy'un" are caught).
   - Number words: reject EN number words and multipliers ("two", "twice", "double", "half"; TR "iki katı", "yarı").
     Do not ban TR "bir" (it is also "a").
   - Causality and medical claims: reject "because", "due to", "injur", "tired because", "çünkü", "yüzünden",
     "nedeniyle", "sakat". Keep the list in one constant.
   - Length: at most 30 words per language.
3. `htg/narration/foundry.py`: `OpenAI` client on `FOUNDRY_PROJECT_ENDPOINT + "/openai/v1"` with
   `get_bearer_token_provider(DefaultAzureCredential(), "https://ai.azure.com/.default")`; chat completions with a
   strict JSON schema `{en, tr, used_facts}`. The prompt gets only `type`, `claim_facts` and the template sentence as a
   style example; rules: one sentence per language, digits only, no number or name not in the facts, no cause, broadcast tone.
   No temperature or other sampling options unless the deployed model accepts them. `PROMPT_VERSION = 1` constant.
4. `htg/narration/service.py`: `narrate_insight(insight) -> Narration`: cache lookup → model → verify both languages →
   on failure one retry with the Verifier reasons as feedback → still failing language falls back to its template.
   Record `source` per language (`llm` / `template`), attempts, reasons, latency.
   Cache: `data/cache/narration/<fp>.json`, `fp = sha256(type, team, player_id, sorted claim_facts, PROMPT_VERSION, model)`.
   Model output is not deterministic; the cache is what makes a match replayable (rule 6).
5. Tests (fake model client, no network): Verifier rejects a changed number, an extra player name, a number word,
   a causal phrase, a too-long sentence; accepts every template sentence for every Insight type on seed 1
   (templates must always pass, otherwise the fallback is broken); service falls back to template after two bad
   drafts; cache hit makes no model call.

## PR 2: Speech, cache and demo pre-generation
1. `htg/speech/azure.py`: Speech SDK, `SpeechConfig(token_credential=DefaultAzureCredential(), endpoint=SPEECH_ENDPOINT)`
   (key fallback from `.env`), output `Audio24Khz48KBitRateMonoMp3`, synthesize to bytes (no speaker output).
   Plain SSML with the voice from `SPEECH_VOICE_TR` / `SPEECH_VOICE_EN`; no styles today.
   Cache `data/cache/audio/<sha256(text, voice)>.mp3`.
2. `htg/narration/pregen.py --seed N [--mode casual]`: run the live pipeline at `speed=inf`, take every `speech`
   decision, narrate + synthesize both languages, write cache, print a summary (count, llm vs template per language,
   total characters sent to TTS, total model tokens).
3. Pick the demo seed from seeds 1-10 (not reporting seeds): a goal plus at least 3 non-chance Insights spoken in one
   10-minute window. Write the seed and the window into `docs/STATUS.md`.
4. Commit `data/cache/` for the demo seed only (text JSON + MP3, expect a few MB). Check the size before committing.
5. Listen to 10 clips per language yourself. Turkish pronunciation of fictional names is the likely weak spot;
   if a name sounds wrong, fix it with an SSML `<sub alias="...">` table, not by renaming players.

## PR 3: live wiring + narration eval
1. `run_local`: keep `LivePipeline` pure. When it emits `speech`, a background task resolves it:
   cache hit → send at once; miss with `HTG_ENV=azure` → narrate + TTS with a 4 s timeout; timeout or error → template
   text, no audio. Never block the replay loop. Drop a resolved non-goal speech that is more than 8 s of match time late.
2. `speech` message adds `source` (`{"en": "llm", "tr": "template"}`), `audio` (`{"en": b64 | null, "tr": b64 | null}`)
   and `duration_s`. Update `docs/design.md` message table if it differs.
3. `web/live.html`: language selector (TR default). If `audio[lang]` exists: `decodeAudioData` and play on the speech bus
   with the existing ducking; else `speechSynthesis`. Caption shows the text and a small tag "verified" (llm) or
   "template". Visual polish is Day 4.
4. `eval/narration.py --seeds 11-30 --limit 100` (needs Azure, run once, a few cents): first-pass Verifier rate,
   fallback rate per language, model latency p50/p95, TTS latency p50/p95. Plus a mutation test that needs no Azure:
   take template sentences, change one number, swap in another player, add a causal phrase; report the catch rate.
   Say in the results file that mutations are synthetic. Write `eval/results/narration.md`.
5. README "Run it locally": add the `HTG_ENV=azure` + pregen commands.

If structured outputs or keyless auth fight you for more than 45 minutes, switch to JSON mode / API keys locally and
note it in STATUS; Day 5 moves to managed identity anyway.
