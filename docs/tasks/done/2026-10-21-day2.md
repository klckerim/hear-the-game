# Day 2 (2026-10-21): engine, detectors, live sound

Goal: a synthetic match replays in real time, the engine turns it into 10 Hz state packets and evidence-backed
Insights, and the browser plays live sound from the stream. Detectors are scored against `truth.json`.
No LLM and no Azure today. Keep it simple; see "Scope and token budget" in CLAUDE.md.

Done when:
- `python -m services.engine.run_local --seed 1 --speed 1 --start-minute 10` streams to `ws://localhost:8765`, and
  opening `web/live.html` plays live sound that follows the match.
- `python -m eval.scenarios --seeds 11-30` prints recall, precision and median detection delay per scenario type
  and writes `eval/results/scenarios.md`.
- `ruff check . && pytest` pass; CI is green on `main`.

Work in three PRs, in this order. `/clear` between PRs.

## PR 1: replay and state engine
1. `htg/adapters/base.py` + `htg/adapters/local.py`: only two Protocols, `EventSource` (async iterator of timed items)
   and `Broadcaster` (`publish(message)`). Local: file event source, WebSocket broadcaster (`websockets`, add to
   dependencies). No `Store` / `BlobStore` yet.
2. `htg/replay.py`: merge `events.jsonl`, `ball.parquet` (10 Hz) and `physical.jsonl` (per minute) into one
   time-ordered stream. Options: `speed` (1, 4, or `inf` for offline/eval), `start_minute`. Deterministic order
   for equal timestamps: ball frame, then events by `seq`, then physical rows.
3. `schemas/state.schema.json`: `t, x, y, team, in_play, danger, pressure, pan, tempo, control`
   (all 0..1 except t/x/y; pan -1..1).
4. `htg/engine/state.py`: `StateEngine` with a pure `step(item) -> list[packet]` (no I/O, no clock):
   - `danger`: xT from `calibration.json` at the ball position in the attacking frame (bilinear), scaled so the
     99th percentile over a match ≈ 1; 0 when the ball is dead.
   - `pressure`: exponentially weighted rate of `pressure` events against the team in possession (half-life ~4 s), mapped to 0..1.
   - `pan`: `htg.pitch.flank_pan` in the attacking frame.
   - `tempo`: on-ball actions per minute over the last 60 s, normalized by the calibration median.
   - `control`: home possession share over the last 5 minutes.
5. Tests: packets validate against the schema; same seed → identical packets; `danger` rises towards goal;
   `pressure` is 0 with no pressure events.

## PR 2: detectors and scenario eval
1. `htg/engine/detectors.py`: each detector consumes engine state + events and emits Insights that validate
   against `schemas/insight.schema.json`, with `claim_facts` holding every number a sentence may use and
   `evidence` listing event `seq`s. Thresholds are parameters, not literals:
   - `pressure_shift`: share of the opponent's actions under pressure, last 5 min vs match so far; fire at ratio ≥ 1.5, ≥ 15 actions; 5-min cooldown per team.
   - `tempo_change`: median gap between a team's on-ball actions, last 5 min vs baseline; fire at ≥ +40%.
   - `flank_overload`: share of a team's passes ending in one flank (attacking-frame y > 42.5 or < 25.5), last 8 min vs baseline; fire at ≥ +50%, ≥ 15 passes.
   - `physical_drop`: a player's high-speed running, last 5 min vs his own earlier average; fire at ≤ 0.6.
   - `chance` (danger peak above threshold, or a shot) and `goal`: priority 4 and 5 milestones.
2. `htg/narration/templates.py`: one deterministic sentence per Insight type, EN and TR. This is the Day-3 Verifier
   fallback and today's narration. Numbers only from `claim_facts`.
   Example: "The Blues have stepped up their press: 44% of the Reds' actions are now under pressure, up from 23%."
3. `eval/scenarios.py`: replay at `speed=inf` through engine + detectors, match Insights to `truth.json`.
   True positive: same type, same team (and same player for fatigue), Insight `t` in `[start, end + 120 s]`.
   Report recall, precision, median delay per scenario type. Tune on seeds 1-10; report on 11-30.
4. Tests: each detector fires on a seed where its scenario exists and stays quiet on a hand-built calm stream.

If a detector cannot reach a reasonable score after two tuning rounds, report the honest number and move on;
do not keep tuning.

## PR 3: Director + live slice
1. `htg/engine/director.py`: small pure function `decide(queue, state, now, mode) -> list[Decision]` (speak / hold / drop):
   speak only when the ball is dead or danger < 0.15; goals immediately; drop expired Insights; no repeat of the same
   type and team within 5 minutes; simple per-mode silence budget. One unit test per rule.
2. `services/engine/run_local.py`: replay → engine → detectors → Director → local WebSocket broadcaster.
   Messages: `state` (batched every 200 ms), `event_cue`, `insight`, `speech` (template text, no audio yet).
3. `web/live.html`: start from `prototype/web/template.html`; replace embedded data with a WebSocket client,
   a 300 ms jitter buffer and match-clock scheduling. Speak `speech` text with the browser's `speechSynthesis`
   until Azure TTS lands on Day 3. Keep the "Dinlemeye başla" button (audio needs a user gesture).
   Visual polish comes on Day 4; today only needs to be functional and tidy.
4. README: add a "Run it locally" section with the two commands above.
